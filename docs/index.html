hardHats

A verdict a chatbot can't fake.

Point hardHats at a file, a folder, or a URL and it returns PASS or FAIL with the finding, because a real check produced it, not an opinion. A chatbot can write a paragraph that looks like a security review. It cannot hand you the file and line of the committed secret. hardHats hands you the line.

# a real check, run on a real tree
$ python -m hardhats.crews crypteng ./src

  [FAIL] private key committed in the clear   src/config/dev.pem:1
  [FAIL] hardcoded token (value redacted)       src/api/client.js:42

== VERDICT: EXPOSED ==   (exit 1 — the build stops here)

Why it holds

A seat is a crew of hats, and a hat is one of two things:

A gate hat

A deterministic function: a real check, a measurement, a linter. Zero tokens, same answer every time.

An LLM hat

A model wearing an instruction, doing only the judgement a rule cannot, handed the facts after they exist.

The gate hats settle the facts. The LLM hats never overrule a gate and are never asked whether something passed. That is the moat: the output is a finding with a location, not a vibe. And the exit code is the verdict, so hardHats drops into any pipeline as a gate. 1 fails the step. Every seat also prints what it did not check, so a clean result never reads as a blank cheque.

Thirty seconds

$ pip install hardhats
$ python -m hardhats.crews                 # list the six inspectors and their checks
$ python -m hardhats.crews security ./src     # every security check that applies
$ python -m hardhats.crews route ./my-project # don't know which? let it pick

Add --json to any inspector or check for a machine-readable envelope a script or another agent can read: verdict, exit, detail.

Six inspectors

Point an inspector at a file, a folder, or a URL. It runs only the checks whose signal is present, composes one verdict, and prints what it did not check.

claims

Does every claim survive a real measurement? A theorem against a kernel, a colour against the perceptual engine, a suite against a mutation.

security

Can a hostile input get control or data? Committed secrets, injection sinks, exploitable CI, missing headers.

contract

Is every declared part present and consistent? API specs, schemas, locale parity, structured data, worker bindings.

reproducible

Will it run the same for someone else? Pinned dependencies, a re-run checklist, archival fixity and open formats.

reach

Can a real person find, receive, and trust the path? Indexability, email auth, live links, human-vs-bot traffic.

safety

Will it harm or break the law against the person on the other end? Photosensitive flash, accessibility, allergen labels, licence, child data.

Under them, the checks, each gated on a real external standard it cannot fake: proof geom vision tests ops balance perf gameperf resilient crypteng inject ghactions sec api schema spec i18n richdata og env method deps repro archive seo deliverability links traffic pwa attribution seizure vpat food license privacy.

And an instrument that refuses to fake a verdict: cipher measures index of coincidence and entropy on a symbol stream and says plainly what stays open. A measurement you can trust, kept apart from a gate.

Gate your repo

As a GitHub Action, point it at the repo or a URL and let the router pick the gates that apply. A hard finding fails the build.

# .github/workflows/gate.yml
name: gate
on: [push, pull_request]
permissions: { contents: read }
jobs:
  hardhats:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: vince-gonzalez/hardhats@v0.5.0

Catch it before it ever leaves your machine, with pre-commit:

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/vince-gonzalez/hardhats
    rev: v0.5.0
    hooks:
      - id: hardhats            # route the repo to every gate that applies
      - id: hardhats-secrets   # or pick the ones you want

The factory

The bench is a production line, not a pile. One command scaffolds a new seat that already obeys the contract: a keyword the dispatcher discovers, a working check, and a fixture pair. It registers and passes the suite the moment it is minted.

$ python -m hardhats.new rustfmt --standard "cargo fmt --check"
  minted seat: hardhats/crews/rustfmt.py
  summon it:   python -m hardhats.crews rustfmt ./src

Then replace the one marked rule with the check your standard defines. A test holds every seat, hand-written or minted, to the same shape, so a seat that drifts off it goes red.

What a real run looks like

Pointed at a 698 KB production browser game, the bench answered in seconds. Not a demo: genuine verdicts, including the ones a human still has to settle.

$ python -m hardhats.crews seo    ./game.html   SEO FLOOR MET
$ python -m hardhats.crews sec    https://…      REVIEW  (required headers present; 3 hardening notes)
$ python -m hardhats.crews og     ./game.html   REVIEW  (add og:image:width/height)
$ python -m hardhats.crews seizure ./game.html  REVIEW  (10 flash candidates flagged to confirm)

That last line is the whole idea. REVIEW is not a pass and not a fail: the bench flagged ten fast-animation and timer sources and named the file and line of each, so a person can open them and settle whether any actually strobes. It does the finding. You keep the judgement.
